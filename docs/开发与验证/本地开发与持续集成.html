当前实现到哪里？

Vue 页面通过开发代理请求 FastAPI；FastAPI 通过 SQLAlchemy + PyMySQL 读取独立 MySQL 数据库。Alembic 首次迁移创建知识领域表并写入“计算机”“英语”。

已支持账号登录、单选每日题、判分、打卡与初始复习日期。完整操作与验收见 每日练习功能与验收。题库管理页面、复习与历史列表、Agent、DuckDB 分析及生产部署尚未实现。当前没有 CD。
接口含义
GET /api/health后端进程存活；不依赖数据库。
GET /api/ready检查 MySQL 连接和迁移版本；成功 200，未迁移或不可连接返回 503。
GET /api/v1/domains读取公开的知识领域，不包含个人数据；数据库不可用时返回 503。

首次准备：在项目根目录执行

以下命令适用于 Windows PowerShell。项目依赖缓存、数据库和日志均留在项目内。Python 依赖版本固定在 backend/requirements.txt，前端依赖由 package-lock.json 锁定。

python -m venv backend/.venv
$env:PIP_CACHE_DIR = "$PWD/build/pip-cache"
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
$env:npm_config_cache = "$PWD/build/npm-cache"
npm --prefix frontend ci

# 使用已安装的 MySQL 程序创建本项目专用实例；按本机位置调整 --bin。
./backend/.venv/Scripts/python.exe tools/dev_mysql.py start --bin "D:/MySQL/MySQL Server 8.0/bin"

Set-Location backend
./.venv/Scripts/python.exe -m alembic upgrade head
Set-Location ..

开发实例仅监听 127.0.0.1:3307，数据位于 build/mysql/data/，不使用 Windows 上已有的 3306 实例。初始化脚本生成随机密码，为开发库与测试库分别创建专用账号，并生成 backend/.env 和 build/mysql/test.env。不会覆盖已有的后端配置，也不会重新初始化已有数据目录。

使用自己准备的 MySQL 实例

复制 backend/.env.example 为 backend/.env，填写本项目独立数据库的连接串，然后执行迁移。账号仅授权本项目数据库，密码中的特殊字符需进行 URL 编码。测试另建空库，名称以 _test 结尾，使用独立连接串。不要使用生产库或其他项目的库。

开发实例停止与再次启动
./backend/.venv/Scripts/python.exe tools/dev_mysql.py stop
./backend/.venv/Scripts/python.exe tools/dev_mysql.py start --bin "D:/MySQL/MySQL Server 8.0/bin"

停止前会校验数据库真实数据目录。若 3307 被其他服务占用，脚本会拒绝接管。初始化中断或缺失凭据时，应检查 build/mysql/mysql-error.log，不要删除数据目录后盲目重建。当前真实停库演练未完成，正常初始化与启动已验证。

启动两个开发终端

终端一，在项目根目录：

Set-Location backend
./.venv/Scripts/python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

终端二，在项目根目录：

npm --prefix frontend run dev

打开 本地页面，应看到计算机、英语两个知识领域；点击领域可切换内容区。展开“服务状态”，应看到“业务服务：已连接”“数据服务：已就绪”。后端交互文档位于 /docs。Vite 将 /api 代理到本机 8000，前端没有数据库密码，也无需开放宽泛的跨域权限。

“重新检查”按钮会重新请求真实数据并保留当前选择；错误和超时会清除过期数据并展示重试入口。前端 dist/ 仅是构建产物，尚未配置生产 API 反向代理。

本地验证

npm --prefix frontend run typecheck
npm --prefix frontend run build

Set-Location backend
./.venv/Scripts/python.exe -m ruff check --config pyproject.toml . ../tools

# 读取本项目初始化脚本生成的测试连接串，不要打印它。
$env:TEST_DATABASE_URL = (Get-Content ../build/mysql/test.env -Raw).Trim().Substring('TEST_DATABASE_URL='.Length)
./.venv/Scripts/python.exe -m pytest -q
./.venv/Scripts/python.exe -m alembic check
Remove-Item Env:TEST_DATABASE_URL
Set-Location ..
  • MySQL 集成测试要求显式配置空测试库，验证空库升级、重复升级、中文种子数据、唯一约束、迁移与模型一致性、降级再升级及接口。
  • 测试结束只按外键依赖清理本次在空测试库中创建的表。未提供测试连接串时，该集成测试会跳过；“仅单元测试通过”不能代表 MySQL 已验证。
  • 另外验证数据库连接失败时存活检查仍成功，就绪检查返回 503，响应不泄露驱动错误与连接凭据；旧迁移版本也不能显示就绪。
  • 本机当前已通过完整 16 项测试、类型检查、构建和浏览器联通检查。Starlette 对测试客户端的 httpx 适配发出一项弃用提示，不影响当前结果；升级测试客户端依赖时需重新验证。

CI 与主分支合并要求

.github/workflows/ci.yml 在指向 main 的 PR 和 main 更新时执行，工作流只读仓库权限，不使用生产密钥，不进行部署。

检查名称内容
Frontend checksNode.js 22、npm ci、TypeScript 检查、Vite 构建。
Backend checksPython 3.13、固定依赖、Ruff、全部 pytest；独立 MySQL 8.0 service container 验证迁移和接口。

CI 数据库使用只供本次任务的测试账号密码，任务结束后销毁。Actions 固定到核实过的 v6 提交 SHA；缓存以依赖锁文件为依据。所有 PR 都运行两项检查，避免路径过滤导致必需检查永久等待。

两项检查首次在 GitHub 成功后，将其加入 main-protection 规则，要求功能分支与 main 保持最新。继续保留 PR、讨论解决、禁止强推与删除、空豁免名单；单人阶段无需其他人的审批。检查设置是否已生效以 GitHub 规则页面回读为准。

标准流程：从最新 origin/main 建功能分支 → 本地验证 → 提交与推送功能分支 → PR 检查 → 通过规则后合并。当前没有 CD。

学习空间界面

左侧固定展示每日练习、个人复习、学习记录三个功能入口，点击切换对应标题与内容；知识领域移入内容区顶部。采用暖灰白背景、浅鼠尾草绿选中态，容器圆角 24px、导航圆角 14px、领域按钮为胶囊形，边框与阴影保持轻量。连接检查默认折叠，顶部入口可直接展开。700px 以下缩窄侧栏，480px 以下将功能导航放到顶部以保留阅读宽度；功能入口通过 aria-current 标注当前页，领域按钮通过 aria-pressed 标注选中项，保留键盘焦点和减少动态效果偏好。

每日练习已接入登录、学习方向、真实题目与提交结果；复习和历史入口暂显示待建设说明。功能与领域选择只存在本次页面会话中，刷新页面回到每日练习，尚未接入持久化偏好或独立路由。

设计参考：shadcn/vue 的可组合、可维护组件思路，以及 Radix Themes 的统一排版与间距。当前是 Vue 与原生 CSS 自行实现，没有复制第三方组件源码，也没有引入整套组件库；后续出现弹窗、复杂表单等需求时，再评估按需复用 shadcn/vue。

本轮验证：类型检查、生产构建；浏览器桌面与窄屏布局、三个功能入口切换、领域切换、连接重新检查及选中项保留。断网与空领域分支已实现，本轮未以浏览器网络注入方式单独验收。
