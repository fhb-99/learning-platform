02 · 已确认的方向，不重复问

  • 毕业设计主线：学习行为分析与可解释复习策略；Agent 四项能力作为后续应用功能。暂无额外强制技术要求，沿用设计；时间较充裕，但未给出明确截止日与每周工时。
  • 每日题：同一学习方向、同一本地日期统一题目；完成状态属于各用户，个性化体现在复习队列。
  • 打卡：合法提交成功按提交日计入。未来 AI 延迟评分不改日期，失败不得记零分或撤销打卡（异步评分尚未实现）。
  • 初始规则：答错或自评“不会”次日复习，连续答对按 1、3、7、14 天递增；记录调度依据。当前仅接入单选题对错，无自评入口；14 天封顶。规则效果仍待实验验证。
  • 复习规则已确认：每题每天最多正式复习一次，答错次日再来、当天可回看解析；最早到期优先，用户/题目仅一个计划，不按学习方向重复建计划；复习沿用上次作答版本。同日复习后又遇到同题每日题，第二次答对不重复推进阶段，答错仍重置次日。
  • 管理员与发布规则：采用普通用户/管理员两级；账号默认无管理权，通过本机命令明确授权，不设置首个注册账号自动成为管理员。题目草稿可改，发布版本只追加；题目标识与所属方向创建后固定，已有作答、已分配每日题和已有复习保持原版本。新每日分配可使用最新发布版；不自动把旧复习迁移到新版。
  • 界面偏好：简洁、平和、柔和灰绿与圆角，避免强烈 AI 宣传感；功能放左侧，右侧学习区宽一些并靠上。当前布局已接受，继续以功能为主。
  • 结果展示：答对、答错都不显示分数；后台判分继续用于调度。未登录先显示登录页，已有有效会话则恢复学习空间。

原设计中的用户端、管理端和 Agent 答疑 / 出题 / 正式评分 / 规划仍属最终范围；分阶段实现不等于已经完成。术语以 CONTEXT.md 为准。

进入“题库管理”，选择领域与方向，新建或编辑题目，先保存草稿，再核对题干、四个不同选项、正确答案、解析与来源并发布。草稿可以不完整；发布必须全部有效。遇到修订冲突先保留自己的必要内容，再重新加载最新草稿；不会静默覆盖另一位管理员的修改。

管理接口前缀为 /api/v1/admin：GET/POST /questions、GET /questions/{id}、PUT /questions/{id}/draft、POST /questions/{id}/publish、GET /questions/{id}/versions。题库按方向 offset 分页，历史版本按 before_version 游标分页，默认每页 20 条。保存携带草稿 revision，发布同一 revision 返回同一版本。

边界：已发布版本通过应用接口只读，没有更新/删除发布版本、撤回、批量改旧复习或网页提权接口。记录草稿最后编辑人及版本发布人；尚无完整审计事件表。不可变性由应用发布路径保证，未增加数据库触发器限制拥有数据库写权限的维护者。新建响应丢失时，重复题目标识会被拒绝，应回到列表查看；草稿保存响应丢失时，重新加载确认实际修订。编辑详情、筛选与页码不做 URL 持久化。

迁移：0004_question_publishing 新增 User.is_admin、独立 QuestionDraft 与版本发布者；既有用户默认普通权限，原题目内容、作答与计划不变。有管理员权限、草稿或管理员发布记录时拒绝降级，不可删除业务数据来强行回退。MySQL DDL 非事务性；跨多个版本降级可能先完成前一迁移，再被后续数据保护拒绝，应检查实际 revision 并按保留数据方案恢复。

新接口、约束和迁移注意事项
接口用途
GET /api/v1/reviews?domain_code=…个人到期队列，按到期日和题目 ID 排序，offset / limit 分页；不返回答案。
GET /api/v1/reviews/{question_id}复习题详情、计划依据和是否可提交；当日已复习则恢复当次结果。
POST /api/v1/reviews/{question_id}/attempts题目版本、basis_attempt_id、答案和幂等键；过期计划拒绝提交，成功追加新作答。
GET /api/v1/historydomain_code、source=all/daily/review、start_date/end_date；按 ID 倒序，before_id 游标分页。
GET /api/v1/history/{attempt_id}仅自己的原始题目版本、作答结果、原定复习日期与当前计划。

Attempt.daily_assignment_id 可空；复习记录填写 review_question_id、review_basis_attempt_id、scheduled_due_date。来源 CHECK 约束确保每日题与复习互斥，用户/复习题/本地日期唯一；原用户/每日题和用户/幂等键约束保留。ReviewPlan 仍以用户/题目为主键。题目目前属于一个学习方向，本轮没有新增多方向映射模型。

调度规则版本更新为 review-v2，保留旧记录的 review-v1。每日题与复习共用事务写入函数，保存记录不会覆盖旧作答；查询历史显示当次安排，同时另列当前计划。列表每页 20 条；复习列表切换分页，历史列表加载更多。筛选条件和列表分页暂不持久化，URL 只保存当前功能、领域和详情定位。

迁移回退：无复习数据时已验证 downgrade/upgrade；产生复习记录后，迁移会明确拒绝降级，避免丢失复习数据。不要删除用户作答来强行降级，必须先制定保留数据的回退方案。当前未验证旧应用在新结构上的完整可用性。
