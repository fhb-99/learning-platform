基于学习行为分析的个性化知识练习与复习系统

一个 Vue 项目提供用户端与管理端两套界面；一个 FastAPI 业务后端；离线学习行为分析；可答疑、出题、评分、规划的 Agent。首批内容是计算机知识与英语，系统模型保持领域无关。

2. 核心业务场景与规则

A. 选择方向并开始练习

用户可选一个或多个方向，例如“C++ 后端”和“英语词汇”。方向是用户偏好，不等于内容分类：一道题可属于“计算机 → 网络 → TCP”，同时标记适合 C++ 后端；英语题可属于“英语 → 词汇 → 技术文档”。系统据方向过滤候选题，再综合未做、到期复习、薄弱知识点和难度组成今日任务。用户可手动换方向，历史记录不丢。

B. 每日一题与打卡

每个方向每天确定一道“每日题”，题目 ID 与本地日期、方向绑定；同一天反复打开仍是同一题。有效打卡定义为完成至少一道正式提交的练习，不以登录或打开页面计算。每日一题完成可计入打卡；时区按用户设置，默认 Asia/Singapore。连续天数按有效打卡日期计算；补签若实现需单独标识，不改写原始事件。

C. 八股题、场景题与单词

客观题提交即判分并展示解析；八股简答与场景题先提交文本，系统按题目版本中的评分要点评分，给出覆盖项、缺失项与依据。英语单词支持“看词选义 / 拼写 / 例句理解”，首版可只完成一种客观题加一种自评闪卡。展示答案后保存用户自评；AI 正式分数与自评同时保留，便于申诉与效果分析。

D. 错题与复习

每次答题形成不可覆盖的 Attempt；复习计划以题目、用户和当前掌握度为单位更新。正式分数低或用户自评“不会”会缩短间隔；答对且自评“能讲清”会延长间隔。复习算法从可解释的规则版开始，并记录规则版本和调度输入；不在第一版宣称真正测出了记忆曲线。

E. Agent 助手

用户可问“TCP 三次握手中第三次有什么作用”“结合我最近错题安排一周计划”。Agent 先检索已发布题库、审核过的解析和该用户授权的历史记录，也可调用联网搜索工具补充新资料；答复显示来源。Agent 可以生成题目草稿和学习计划，也可以执行站内自动操作，例如添加今日任务、调整复习日期或更新自己生成的草稿。高影响内容修改保留审核/撤销入口。

3. 技术架构与技术栈

已确定的核心技术栈：Vue 3 + TypeScript、Python FastAPI、MySQL、DuckDB + Parquet。模型能力通过后端调用外部 API；业务 Agent 的检索、评分、规划和操作规则由本系统实现。首版不使用 Go，也不要求在生产服务器运行 Spark。
用户端 Vue 3 + TS→FastAPI 业务后端→MySQL 业务库→离线分析 DuckDB / Parquet
管理端 Vue 3 + TS→同一后端 RBAC→后台任务 / Agent 模块→审核记录与分析结果
组件建议选择理由 / 取舍
用户端 / 管理端Vue 3 + TypeScript + Vue Router + Pinia；同一项目中用不同路由与布局呈现用户端和管理端两套界面共享登录、接口和基础组件；管理权限仍由后端校验。复杂图表用 ECharts。
业务后端Python FastAPI 单体服务，按 auth/content/practice/review/analytics/agent 模块组织Python 方便学习分析与模型接入；单体减少部署与事务复杂度。接口生成 OpenAPI 文档。
业务库MySQL（InnoDB）沿用已熟悉的 MySQL；题目、版本、用户、答题、计划和审计使用关系表、唯一约束与事务。先建必要索引，首版不加缓存。
后台任务MySQL 任务表 + 独立 worker；定时触发每日任务与统计简答题正式 AI 评分需要持久任务、失败重试和幂等，不能只依赖请求结束后的进程内任务；首版仍是单体后端。
分析存储按日导出匿名化事件为 Parquet；DuckDB 做离线聚合Python 可复用同一数据处理语言；DuckDB 直接查询 Parquet。只有导师要求分布式技术时，才增加 Spark 离线对照实验。
Agent后端调用外部模型 API；自行实现题库检索、评分规则、学习计划及受控站内工具不用训练模型，也不只做 API key 聊天框。密钥仅在后端；模型输出先校验，再按用户权限执行工具并记录依据。

核心栈已经确认；具体依赖版本与模型服务商在实现时锁定。资料：Vue、FastAPI、MySQL InnoDB、DuckDB Parquet。

4. 前后端如何交互

动作示例接口后端行为前端反馈
加载今日任务GET /api/v1/today?track_id=...按用户、方向、日期查询或幂等生成任务每日题、复习题、单词任务、打卡状态
提交客观题POST /api/v1/attempts校验题目版本、判分、写 Attempt、更新 ReviewPlan 和打卡分数、解析、下次复习日期
提交简答/场景题POST /api/v1/attempts/subjective先落提交记录，再排队调用 Agent 评分；保存评分依据和模型版本任务状态；完成后显示分数、覆盖项、申诉入口
查学习报告GET /api/v1/analytics/me读预计算用户指标，不扫描所有原始事件趋势、薄弱点、复习完成率
Agent 对话POST /api/v1/agent/sessions/{id}/messages鉴权、检索、联网搜索（按需）、工具调用、审计流式回答、引用、后续操作建议
管理端发布题目POST /api/v1/admin/questions/{id}/publish检查必填字段、答案、版本、权限，生成不可变发布快照发布结果与错误定位

幂等与一致性：提交接口携带请求幂等键；同一提交重试不能新增两条成绩。客观题的 Attempt、打卡、复习计划在一个事务中处理；AI 评分是异步状态，完成后再更新正式分数与计划。报告标记统计截止时间，避免把延迟分析误认为实时数据。

6. 学习行为分析与“大数据”部分

Attempt / CheckIn / Review 事件→脱敏与去重→按日期/领域 Parquet→聚合与模型实验→学习看板 / 推荐策略

在线业务指标

  • 每日答题量、正确率、完成率、连续打卡天数。
  • 知识点薄弱度：近期得分、遗忘次数、复习逾期情况。
  • 题目质量：作答量、争议评分率、异常高错率。
  • 复习效果：到期题完成率、复习前后分数变化。

离线实验与验收

  • 公开数据集与本系统用户数据分开存储；记录来源、许可、采样、缺失、重复。
  • 用公开学习行为数据验证 ETL、分区、聚合吞吐和推荐算法离线指标。
  • 用本系统真实试用记录评估产品可用性，不能用英语数据直接证明计算机八股推荐有效。
  • 对照简单基线（随机或固定间隔），汇报命中率/误差及样本量；不预先承诺提升幅度。

可用 EdNet 官方学习行为数据做离线规模实验。该数据来自英语考试学习，许可为研究用途 CC BY-NC；应仅作为研究数据，且不混入本站真实用户的掌握度结果。个人毕设初期的实际用户量不足以称为海量数据，因此“数据分析系统”与“公开大规模数据实验”要分别写进论文。数据论文

7. Agent 能力与控制边界

能力输入与动作验收与保护
答疑检索已审核题目、解析、用户授权的历史；必要时联网搜索回答附来源，区分内部题库与网页；未检索到可靠依据时承认不确定
题目生成按方向、知识点、题型生成题干、答案、评分要点先为草稿；去重、格式检查，管理员可审核发布；自动更新只限可回滚草稿
简答/场景题评分使用题目版本的评分要点、用户原答案输出分数和逐点证据分数直接进入成绩和复习计划；保存模型/提示词/评分标准版本，支持申诉和重新评分
学习规划读薄弱点、到期题与目标方向，生成周计划并可创建站内任务记录每次任务变更；用户能查看、撤销和关闭自动规划
关键取舍：你要求 AI 分数直接决定成绩，所以首版必须有固定评分 rubric、结构化输出校验、低置信度标记、申诉更正、评分日志，以及一组人工标注样本做一致性测试。不能把模型一句“回答不错”当正式评分依据。联网网页与题目文本也可能包含恶意指令；检索内容只作为资料，工具调用始终由后端权限与参数规则控制。

最小工具集：search_published_content、get_my_learning_summary、web_search、create_question_draft、update_my_plan。每个工具有输入模式、调用者权限、速率限制和审计记录。Agent 不直接执行任意 SQL、访问所有用户数据或触碰服务器文件。

8. 范围、实施顺序与验收

阶段交付验收
第 1 阶段：基础系统Vue 用户端与管理端页面、登录、领域/方向、题库管理、版本发布管理员发布题目，用户只能看到适合自己方向的发布版
第 2 阶段：练习闭环每日一题、客观判分、打卡、错题、复习队列重复提交幂等，连续打卡与复习日期计算可重现
第 3 阶段：分析闭环埋点事件、每日聚合、薄弱点看板、Parquet 离线实验原始记录与汇总结果对得上；有基线和处理性能记录
第 4 阶段：Agent答疑、出题草稿、正式评分、计划工具答复有来源；评分有逐点依据与申诉；动作可审计、可回滚

单人毕设必须守住的验收边界

  • 至少准备计算机与英语两个领域的合法题目样本；每种首版题型均能完成“选题→作答→评分→复习→报告”。
  • 对 AI 评分建立人工标注的小测试集，报告与人工分数的差异和争议样例；不保证所有开放题绝对正确。
  • 公开数据实验展示数据清洗、分区与分析；真实用户试用结果单独报告。
  • Agent 联网搜索、生成题目、自动规划都要有失败/超时/无模型密钥时的可用降级路径。

不纳入首版：在线编程判题、社交排行、大规模多租户运营、未经授权抓取题库或用户资料。它们可以作为后续扩展，不影响题目名称的开放性。

9. 部署与运行方案

learn.gentleyun.cn→Nginx / HTTPS→Vue 静态页面 + FastAPI→独立 MySQL 数据库

保留现有博客域名入口。若可管理 gentleyun.cn 的 DNS，则新增 learn.gentleyun.cn 指向同一服务器；为新系统配置独立的 Nginx 虚拟主机和 HTTPS，用户端放在根路径，管理端放在 /admin/，/api/ 转发到只监听本机空闲端口的 FastAPI。先核对服务器当前配置和资源占用，再确定端口与部署方式；本方案不是已完成的线上配置。

  • 新系统单独创建 MySQL 数据库与低权限账户，不读写博客的 PocketBase 数据；模型 API key 仅保存在后端运行环境。
  • FastAPI 服务、AI 评分 worker 和定时统计分别可观测、可重启；正式评分任务持久化到 MySQL，模型不可用时保留待处理状态并允许重试。
  • 原始学习记录留在业务库；定时脱敏导出 Parquet，DuckDB 运行离线分析后将报告结果写回业务库供页面读取。服务器首版不常驻 Spark。
  • 部署验收包括登录与权限、完整答题闭环、评分失败恢复、统计截止时间、数据库备份恢复，以及博客原有入口可用。

开发期先用本机环境跑通完整流程；上线前核对 DNS 控制权、证书申请、服务器内存/磁盘和现有 Nginx 转发。不得将模型密钥或数据库密码打包到前端。

10. 待导师确认的事项

  1. 学院是否要求指定技术栈或必须部署 Hadoop/Spark；若有，离线实验层可调整，业务层不必跟着拆成分布式。
  2. 毕设评价更看重系统工程、推荐算法还是数据处理性能；这决定论文重点和实验指标。
  3. Agent 自动评分与联网搜索是否被导师视为可接受的核心功能，是否要求本地模型或可离线演示。
